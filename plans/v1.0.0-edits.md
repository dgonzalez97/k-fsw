# 1.0.0 edit instructions

Companion to the [release plan](v1.0.0.md). These are proposed edits, not applied
patches. No functions changed; no builds, runtime tests, or HIL run.

Use the release plan's immutable commits and line numbers. The functions below
were also checked against `k-fsw@9710008`, `kfsw-services@44c0a62`, and
`kfsw-modules@f7b9593`; their relevant source files are unchanged. The newer
parameter and button work stays outside these tasks.

Each task inherits the file scope and dependencies in the release plan. Locate
the named function first; if its condition has changed, recheck the finding
before editing. Code blocks show proposed replacements for the named fragment.
New state and helpers are identified explicitly. Ordered steps describe changes
that need to land together; they are not standalone patches.

## D01 — Hand the watchdog over once

**Edit:** `kfsw-platform/src/watchdog.c:68`, `watchdog_keepalive_handler()`.

Replace the state-only decision:

```c
running = (watchdog_state.state == KFSW_PLATFORM_WATCHDOG_RUNNING);
```

with:

```c
running = watchdog_state.keepalive_owned &&
          (watchdog_state.state == KFSW_PLATFORM_WATCHDOG_RUNNING);
```

Keep the ownership check, feed, and reschedule inside the existing
`watchdog_lock` critical section. Remove the reschedule after unlocking: a
saved `running == true` must not enqueue work after release changes ownership.
The pinned Zephyr reschedule API permits nonblocking interrupt-context use.

At `:208`, `kfsw_platform_watchdog_release()`, clear ownership under that lock,
unlock, then replace `k_work_cancel_delayable()` with
`k_work_cancel_delayable_sync()`. Use separate sync storage for each call and
follow Zephyr's coherent-memory requirement where enabled. Document this as a
thread-context handover; reject forbidden contexts before changing ownership.
It must not run from the system workqueue that executes the keepalive. Never
wait for cancellation while holding `watchdog_lock`.

**Also edit:** `kfsw-services/src/health/health.c:360`,
`kfsw_health_check_interval_ms()`, and `:270`, `kfsw_health_start()`.

Replace “timeout is zero, accept” with these cases:

| Condition | Result |
| --- | --- |
| Interval is zero | `-EINVAL` |
| Watchdog hardware exists, but has not initialised | Check against its configured timeout |
| Watchdog is initialised | Check against its reported timeout |
| Platform has no watchdog | Keep the existing no-device behaviour |
| Interval exceeds `kfsw_platform_watchdog_feed_interval_ms(timeout)` | `-ERANGE` |

Keep device knowledge in platform. Add a small public query for the configured
timeout, returning zero when no device is selected; this is an explicit API
addition, not a new field silently changing existing status semantics. Validate
the compiled health default before restore. Reject an invalid restored value
before it replaces that default. Revalidate under the health state lock before
release, and serialise start with interval changes and repeated starts. Failed
validation must leave platform keepalive ownership intact.

**Regression:** pause the handler at handover on a preemptible/SMP test setup;
after release returns, no platform feed or reschedule occurs. Check 2666 ms is
accepted and 2667/5000 ms rejected for an 8000 ms watchdog. Exercise restore
before initialisation, invalid compiled defaults, and no-device startup. The
default cooperative single-core setup alone does not exercise this race.

## D02 — Collect without holding the HK state lock

**Edit:** `kfsw-services/src/hk/hk.c:503`, `kfsw_hk_collect()`;
`:405`, `kfsw_hk_collect_report()`; `src/hk/hk_internal.h:11`, report state.

Replace the current `hk_lock → collect_report() → PARAM/CSP/storage` sequence:

1. Acquire a new static collection mutex. It owns the existing static sample
   scratch and the remote collector's static search/value arrays.
2. Under `hk_lock`, reject an undefined report, then copy only entries, count,
   widths, offsets, payload size, sequence, and a new definition generation.
   Use a small private definition structure; do not copy `struct kfsw_hk_report`
   and its ring.
3. Release `hk_lock`. Collect into scratch. Pass a local entry-failure count
   through the private collection helpers instead of mutating global statistics
   from the unlocked collection path.
4. Reacquire `hk_lock`. If undefined or its generation differs, discard scratch
   and return `-EAGAIN`. Otherwise commit the sample, sequence, and counters.
   Release `hk_lock` on every outcome.
5. Flush pending store records from stable copies outside `hk_lock`; finally
   release the collection mutex. Do not pass an unlocked live ring to the
   current `kfsw_hk_store_flush()`.

At `kfsw_hk_define():202` and `kfsw_hk_clear():296`, increment generation on each
definition replacement or clear. Keep generations outside the structures these
functions zero, so clearing then defining cannot reuse the old generation.

Storage needs its own serialisation with clear/redefinition. Acquire storage
ownership before the final generation check and before any clear/redefinition
that changes its layout. Order these locks as collection, storage, then HK;
paths needing only storage and HK use that same order. Drop HK during file I/O.
This prevents an old-layout write finishing after a new definition is published.
Use bounded record copies, with no new heap allocation.

**Regression:** hold a remote read, concurrently sample HK statistics through
PARAM and read an existing HK sample; both reads finish. Clear/redefine during
collection returns `-EAGAIN` and publishes no old-layout frame. Overlap manual
and scheduled collection, and delay a store write while reading the ring.

**Second PR:** `:678`, `pull_remote_batch()`.

The minimum missing-END correction is:

1. Set `*consumed = 0U` on entry. Add `bool end_seen = false;` outside the loop.
2. After a valid packet is decoded successfully, assign `end_seen = end`.
3. After the read loop and before the success branch, add:

```c

    result = -ETIMEDOUT;
}
```

That fixes false success after a partial reply; it does not establish value
coverage. Complete the same task by decoding into bounded private storage,
tracking requested IDs/array offsets, and checking type and width. Only commit
values and set `*consumed = added` if END arrived and every requested value was

replace that use with private decoding, rather than adding coverage checks
around writes that have already escaped. Keep this inside the adapter, using
the pinned serializer; do not patch vendor sources.

admission, connection setup, and all receives. Pass the remaining budget to
each wait; if it is zero, stop with `-ETIMEDOUT`. Do not reset the deadline per

`csp_send()` consumes ownership even on transmit failure.

**Regression:** allocation fails once then recovers without losing an ID;
half-list disconnect never becomes cached; one valid value packet without END
returns `-ETIMEDOUT`; END with a missing value returns `-EBADMSG`. Verify private

## D07 — Schedule from due times, not completion delays

**Edit:** `kfsw-services/src/hk/hk_thread.c:29`, `hk_collector()`;
`src/hk/hk.c:673`, `kfsw_hk_set_period()`.

Keep one collector thread. Replace the one-time `now` at the top of the scan
with a fresh monotonic read for each report. Under `hk_lock`, select work only
when enabled, clock-valid, defined, period nonzero, and `now >= next_uptime_ms`.
Save due time, period, definition generation, and a new schedule revision.

Replace `report->next_uptime_ms = now + (int64_t)report->period_ms` with this
post-collection calculation. These are proposed local names, with
`period_ms > 0` and `finished_ms >= due_ms`:

```c
int64_t skipped = (finished_ms - due_ms) / period_ms;
int64_t next_due = due_ms + (skipped + 1) * period_ms;
```

Count one attempted collection and `skipped` missed slots, including when the
attempt produces an incomplete sample. Use a saturating missed counter. Before
writing `next_due` under `hk_lock`, require both saved revisions to match.
Also recheck that periodic collection is enabled and this report's period is
nonzero. Otherwise keep the newer schedule. D02's definition generation alone
does not detect a period change.

At `set_period()`, retain `0` as disabled. For a nonzero period set first due to
`monotonic_now + period`, increment schedule revision, and give a new collector
wake semaphore. Clear, redefine, enable/disable, and beacon interval changes
also wake it. In `kfsw_hk_set_enabled():350`, increment the affected schedule
revisions when enabled state changes. Do not drain a wake after taking a
schedule snapshot: a concurrent change must not be lost.

Wait until the earliest report or beacon deadline, or a configuration wake.
Refresh time after blocking collection before beacon processing. Keep the
existing 200 ms ceiling for clock-validity polling until a clock-change wake
exists; an indefinite semaphore wait would miss clock recovery. When the clock
is invalid, collect nothing on schedule. On recovery, try once and skip elapsed
slots. Wall-clock changes never change monotonic due times.

D04's deadline must reach every remote batch and lock wait. Give each report a
total budget; on expiry, preserve collected values, mark remaining entries
incomplete, and proceed to the next report. Priority changes alone do not bound
that wait. Fix beacon state synchronisation in `src/hk/hk_beacon.c` if its due
times are now read by the collector; use the same HK state lock and copy state
before sending, never hold it across CSP I/O.

**Regression, with a 1000 ms period:**

| Saved due | Start | Finish | Next due | Missed slots |
| --- | --- | --- | --- | --- |
| 1000 | 1000 | 1250 | 2000 | 0 |
| 1000 | 1000 | 3500 | 4000 | 2 |
| 1000 | 3500 | 3600 | 4000 | 2 |
| 1000 | 1000 | 2000 | 3000 | 1 |

Change period to 5000 ms at time 1100 while collection runs: its new due time
6100 must survive completion. Disable during collection: no reschedule. Add
two-report, clock loss/recovery, beacon-only, and silent-node cases. No catch-up
burst. Measure actual wake lateness under concurrent traffic before claiming
deterministic timing on NUCLEO.

## D09 — Interrupt procedure waits and reject invalid numbers

**First PR:** `kfsw-services/src/fbo/fbo.c:168`, `run_line()`; `:234`,

## D12 — Distinguish active HK settings from saved settings
